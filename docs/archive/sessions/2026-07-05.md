## Pre-Implementation Considerations

Before writing the module, reviewed `esm2_wrapper.py`, `dataset.py`, `soft_prompt.py`,
and `docs/STATUS.md` to confirm the interface. Two things shaped the design:

- **Input width is mode-dependent.** `ESM2Wrapper` outputs `(B, embed_dim)` in
  `internal` mode but `(B, embed_dim + N*embed_dim)` in `external` mode — the
  classifier takes `input_dim` as a constructor arg rather than assuming a fixed
  width.
- **This is multi-task, not single-label.** The 2026-07-02 session already locked
  in three targets with equal loss weights (α = β = γ = 1): `drug_class`
  (multi-label), `resistance_mechanism` (single-label), `amr_gene_family`
  (single-label). This ruled out a single-head design.

## Implementation

### `src/models/classifier.py` (`ClassifierHead`)

Shared trunk → three independent heads:

- **Trunk:** `Linear(input_dim, hidden_dim)` → `ReLU` → `Dropout(dropout)`.
- **Heads:** `Linear(hidden_dim, num_drug_classes)`,
  `Linear(hidden_dim, num_mechanisms)`, `Linear(hidden_dim, num_families)`.
- `forward(x)` returns a dict — `{"drug_class": ..., "resistance_mechanism": ...,
  "amr_gene_family": ...}` — rather than a single tensor, so `loss.py` can apply
  `BCEWithLogitsLoss` / `CrossEntropyLoss` per key without unpacking a fixed
  concatenated tensor.
- All dims (`input_dim`, `hidden_dim`, `dropout`, and all three vocab sizes) are
  constructor args — none hardcoded. `hidden_dim`/`dropout` come from config;
  vocab sizes come from `card_parser.get_label_vocabularies()`.
